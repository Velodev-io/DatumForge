# CM5.a implementation plan

**Goal:** Define bounded, executable contour/start/end/thickness/draft contracts.
**Spec:** [CM5.a intent](../../decisions/core-modeling-cm5-intent.md).
**Architecture:** Immutable kernel-free CBOR intent parser in `cad_feature_model`,
with explicit typed references and existing shared dependency graph validation.
**Execution:** In-session TDD from the user's CM5.a go-ahead and authorized core
specification. No automatic delegation or worktree/dependency duplication. Use
the clean checkout's separate review branch and pinned existing build.

## Constraints and review focus

Preserve native worker ownership, SI semantics, physical 8 GB baseline, existing
admission and deferred 6.1b/6.4c/7.4c. Stop before CM5.b and Module 11. Exact
connectivity/body/face resolution is not structural reference validation. Test
inactive fields, asymmetric second direction, midplane total values, surface
dependencies surviving serialization, and graph kind/order/cycle mistakes.

## Tasks

1. Add `tests/core_modeling/feature_intent.cpp` and register `cm5.intent`.
   First compile against the absent `features/ModelingIntent.hpp` to retain an
   expected API red. Define legal extrude/revolve/draft round trips and ensure
   the legacy accepted feature parser refuses them.
2. Add `src/features/ModelingIntent.hpp/.cpp` to `cad_feature_model`.
   `ModelingIntent::parse(const QCborMap&)` validates and owns the immutable map;
   `map() const`, `graphNode() const` and
   `graph(const std::vector<evaluation::GraphNode>&, QStringList, QString) const`
   expose value serialization and structural dependency validation.
   Implement the minimal first legal case, then add failing behavioral test
   groups for profile modes, starts/ends, thin/draft and graph failures before
   each corresponding implementation.
3. Build all targets, run enabled CTest, pinned format and both changed C++
   units' Clang analysis; check ownership, research isolation, coverage and
   specifications. Retain logs/source identity under
   `docs/testing/artifacts/core-modeling/cm5-a-20261103/`.
4. Record contract-only completion separately from engine/native/full acceptance.
   Self-review the parser and tests, update scoped evidence and task status,
   commit/push the review branch and verify its remote identity. Do not merge.

Each implementation step follows failing test, minimal code, passing test.
